Module 1 — Compilation : du C# au processeur

  • Le compilateur Roslyn transforme le C# en IL (Intermediate Language), stocké dans une DLL.
  • Au lancement, le CLR (Common Language Runtime) charge l'IL.
  • Le JIT (Just-In-Time) compile chaque méthode en code machine natif au premier appel.
  • Le CLR gère aussi la mémoire (Garbage Collector), la sécurité des types et les exceptions.
  • Conséquence : un même binaire tourne sur Windows, macOS et Linux tant qu'un runtime .NET est présent.

Module 2 — Types valeur et types référence

  • Toute donnée en C# a un type connu à la compilation.
  • Type valeur : la variable contient la donnée (pile). Copie = duplication. Ex. int, double, bool, struct.
  • Type référence : la variable contient une adresse vers l'objet (tas). Copie = deux variables pointent le même objet. Ex. string, class, tableaux.
  • string est un type référence mais immuable : il se comporte comme une valeur.
Copie de valeur vs copie de référence
int a = 10;
int b = a;      // copie de la valeur
b = 20;
Console.WriteLine(a); // 10 — a n'a pas changé

int[] t1 = { 1, 2, 3 };
int[] t2 = t1;  // copie de la référence
t2[0] = 99;
Console.WriteLine(t1[0]); // 99 — même tableau !

Module 2 — Conversions de types

Conversions
// Implicite : sans perte, automatique
int i = 100;
long l = i;        // int → long
double d = i;      // int → double

// Explicite (cast) : perte possible, à demander
double prix = 19.99;
int arrondi = (int)prix;        // 19 (troncature)
int ok = (int)Math.Round(prix); // 20

long grand = 3_000_000_000;
int debordement = (int)grand;   // -1294967296 !

// Classe Convert : conversions entre types de base
string s = "123";
int n = Convert.ToInt32(s);     // 123
bool b = Convert.ToBoolean("true");

// checked : lève une exception en cas de débordement
int sur = checked((int)grand);  // OverflowException
  • Implicite : autorisée quand aucune information ne peut être perdue (petit → grand).
  • Explicite : syntaxe (Type)valeur. Le développeur assume le risque de perte.
  • Le cast double → int tronque (ne pas arrondir). Utiliser Math.Round, Math.Floor, Math.Ceiling.
  • Le débordement (overflow) est silencieux par défaut : checked le rend explicite.
  • Convert.ToXxx accepte des chaînes mais lève FormatException si le format est invalide.

Module 2 — Parse et TryParse

Saisie sécurisée
// Parse : lève FormatException si l'entrée est invalide
int n1 = int.Parse("42");
// int n2 = int.Parse("abc"); // FormatException

// TryParse : renvoie bool, résultat via paramètre out
if (int.TryParse("42", out int n2))
{
    Console.WriteLine($"Nombre valide : {n2}");
}
else
{
    Console.WriteLine("Saisie invalide");
}

// Idiome courant pour une saisie utilisateur
Console.Write("Votre âge : ");
string saisie = Console.ReadLine() ?? "";
while (!int.TryParse(saisie, out int age) || age < 0)
{
    Console.Write("Entrée invalide, réessayez : ");
    saisie = Console.ReadLine() ?? "";
}
  • Parse : quand on est certain du format (données internes).
  • TryParse : quand la donnée vient de l'extérieur (clavier, fichier, réseau). Jamais d'exception.
  • Le paramètre out permet de déclarer la variable directement dans l'appel : out int n.
  • Disponible sur tous les types numériques, bool, DateTime, Guid, enum…
  • Attention à la culture : double.Parse("3,14") dépend des paramètres régionaux. Préférer CultureInfo.InvariantCulture pour les fichiers.
Règle du TP 1 : aucune saisie utilisateur ne passe par Parse.

Module 2 — Chaînes de caractères et interpolation

Chaînes
string prenom = "Alice";
int age = 30;

// Concaténation (à éviter au-delà de 2 morceaux)
string s1 = "Bonjour " + prenom + ", " + age + " ans";

// Interpolation : préfixe $, expressions entre accolades
string s2 = $"Bonjour {prenom}, {age} ans";

// Format numérique dans l'interpolation
decimal prix = 1234.5m;
Console.WriteLine($"{prix:C}");      // 1 234,50 €
Console.WriteLine($"{prix:N2}");     // 1 234,50
Console.WriteLine($"{0.256:P1}");    // 25,6 %
Console.WriteLine($"{42:D5}");       // 00042

// Alignement (largeur, négatif = à gauche)
Console.WriteLine($"|{prenom,-10}|{age,5}|");
// |Alice     |   30|

// Chaîne verbatim : pas d'échappement des \
string chemin = @"C:\Users\alice\docs";

// Chaîne brute (C# 11+) : plusieurs lignes, guillemets libres
string json = """
    { "nom": "Alice" }
    """;
  • Une string est immuable : chaque modification crée une nouvelle chaîne.
  • L'interpolation $"…" est la forme recommandée : lisible et performante.
  • Spécificateurs de format après : — C monnaie, N nombre, P pourcentage, D entier, F2 deux décimales.
  • @"…" désactive les séquences d'échappement (chemins Windows, regex).
  • """…""" (chaîne brute) : idéal pour JSON, SQL, HTML multi-lignes.

Module 3 — Opérateurs

Opérateurs
int a = 17, b = 5;

// Arithmétiques
a + b;  a - b;  a * b;
a / b;    // 3  (division entière !)
a % b;    // 2  (reste)
17.0 / 5; // 3.4 (dès qu'un opérande est double)

// Incrémentation
int i = 0;
i++;   // i = 1  (post : renvoie l'ancienne valeur)
++i;   // i = 2  (pré : renvoie la nouvelle valeur)
i += 10;  i -= 3;  i *= 2;  i /= 4;

// Comparaison → bool
a == b;  a != b;  a > b;  a >= b;

// Logiques (court-circuit : le 2e terme n'est évalué que si nécessaire)
bool majeur = age >= 18 && aPermis;
bool acces = estAdmin || estProprietaire;
bool ferme = !ouvert;

// Priorité : * / % avant + -, comparaison avant && puis ||
int r = 2 + 3 * 4;      // 14
int r2 = (2 + 3) * 4;   // 20
  • Piège n°1 : int / int donne un int. 7 / 2 == 3. Convertir un opérande en double pour une division réelle.
  • % (modulo) : tester la parité (n % 2 == 0), cycler dans un tableau, extraire des chiffres.
  • && et || court-circuitent : obj != null && obj.Valide est sûr.
  • = affecte, == compare. Le compilateur refuse if (a = 5) car int n'est pas bool.
  • En cas de doute sur la priorité : des parenthèses.

Module 3 — Opérateurs null et ternaire

Null et ternaire
string? saisie = Console.ReadLine();

// ?? : valeur par défaut si null
string nom = saisie ?? "anonyme";

// ??= : affecte seulement si null
saisie ??= "valeur par défaut";

// ?. : accès sécurisé, renvoie null au lieu de lever
int? longueur = saisie?.Length;
string? majuscule = saisie?.Trim()?.ToUpper();

// Combinaison classique
int taille = saisie?.Length ?? 0;

// Ternaire : condition ? siVrai : siFaux
int age = 20;
string statut = age >= 18 ? "majeur" : "mineur";

// Ternaire imbriqué : lisible seulement sur 2 niveaux max
string cat = age < 13 ? "enfant"
           : age < 18 ? "ado"
           : "adulte";

// Types nullable pour les valeurs : int?, double?, bool?
int? score = null;
if (score.HasValue) Console.WriteLine(score.Value);
Console.WriteLine(score.GetValueOrDefault(-1)); // -1
  • null = « absence de valeur ». Y accéder lève NullReferenceException, l'erreur n°1 en C#.
  • ?? : « sinon ». Remplace un if (x == null) x = ….
  • ?. : « si non null, alors ». Toute la chaîne devient null dès le premier maillon null.
  • int? est un raccourci pour Nullable<int> : un entier qui peut ne pas avoir de valeur (ex. colonne SQL nullable).
  • Le ternaire remplace un if/else qui n'affecte qu'une valeur. Au-delà de 2 niveaux, écrire un switch.

Module 3 — if / else et switch (instruction)

Conditions
int note = 14;

if (note >= 16)
{
    Console.WriteLine("Très bien");
}
else if (note >= 12)
{
    Console.WriteLine("Bien");
}
else
{
    Console.WriteLine("À revoir");
}

// switch classique sur une valeur
string choix = Console.ReadLine() ?? "";
switch (choix)
{
    case "1":
        Console.WriteLine("Ajouter");
        break;
    case "2":
    case "3":                     // plusieurs étiquettes
        Console.WriteLine("Lister ou rechercher");
        break;
    case "q":
        return;                   // quitte le programme
    default:
        Console.WriteLine("Choix inconnu");
        break;
}
  • Accolades toujours, même pour une seule instruction : évite les erreurs lors d'ajouts ultérieurs.
  • Les conditions sont évaluées de haut en bas : ordonner du cas le plus restrictif au plus général.
  • switch : chaque case doit se terminer par break, return ou throw. Pas de « fall-through » implicite comme en C.
  • Plusieurs étiquettes peuvent partager un bloc (case "2": case "3":).
  • default : le cas « tout le reste ». À prévoir systématiquement dans un menu.

Module 3 — switch expression et pattern matching

Pattern matching
// switch expression : renvoie une valeur, pas de break
int note = 14;
string mention = note switch
{
    >= 16 => "Très bien",
    >= 14 => "Bien",
    >= 12 => "Assez bien",
    >= 10 => "Passable",
    _     => "Insuffisant"     // _ = défaut
};

// Patterns combinés
string categorie = age switch
{
    < 0            => throw new ArgumentException("Âge négatif"),
    < 13           => "enfant",
    >= 13 and < 18 => "ado",
    >= 65          => "senior",
    _              => "adulte"
};

// Pattern sur tuple : plusieurs valeurs à la fois
string acces = (role, heure) switch
{
    ("admin", _)               => "total",
    ("user", >= 8 and <= 18)   => "horaires bureau",
    ("user", _)                => "refusé",
    _                          => "inconnu"
};

// is avec pattern
if (saisie is not null and { Length: > 0 })
    Console.WriteLine("Saisie non vide");
  • La switch expression (C# 8+) est une expression : elle produit une valeur, s'affecte à une variable, se renvoie d'une méthode.
  • Les cas sont des patterns : constante, relationnel (>=), combinés (and, or, not), tuple, type (module 7), propriété ({ Length: > 0 }).
  • L'ordre compte : premier pattern qui correspond gagne. Le compilateur avertit si un cas est inatteignable ou si la couverture est incomplète.
  • _ est le discard : correspond à tout.
  • Préférer la switch expression au switch instruction dès qu'on calcule une valeur.

Module 3 — Boucles

Boucles
// for : nombre d'itérations connu
for (int i = 0; i < 5; i++)
{
    Console.WriteLine(i);       // 0 1 2 3 4
}

// foreach : parcourir une collection (lecture seule)
string[] noms = { "Alice", "Bob", "Chloé" };
foreach (string nom in noms)
{
    Console.WriteLine(nom);
}

// while : condition testée avant chaque tour
int essais = 0;
while (essais < 3 && !Authentifier())
{
    essais++;
}

// do…while : exécuté au moins une fois (menus !)
string choix;
do
{
    Console.WriteLine("1) Ajouter  2) Lister  q) Quitter");
    choix = Console.ReadLine() ?? "";
} while (choix != "q");

// Boucle inversée
for (int i = noms.Length - 1; i >= 0; i--)
    Console.WriteLine(noms[i]);
  • for : trois parties — initialisation ; condition ; incrément.
  • foreach : la forme la plus sûre et la plus lisible pour parcourir. Impossible de modifier la collection pendant le parcours.
  • while : « tant que ». Vérifier que la condition finit par devenir fausse (sinon boucle infinie).
  • do…while : le corps s'exécute avant le test. C'est la structure naturelle d'un menu console.
  • Indices : un tableau de n éléments va de 0 à n - 1. noms[3] lève IndexOutOfRangeException.

Module 3 — break, continue et boucles imbriquées

Contrôle de boucle
// break : sortir immédiatement de la boucle
foreach (var nom in noms)
{
    if (nom == "Bob")
    {
        Console.WriteLine("Trouvé !");
        break;
    }
}

// continue : passer directement au tour suivant
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0) continue;   // saute les pairs
    Console.WriteLine(i);       // 1 3 5 7 9
}

// Boucles imbriquées : table de multiplication
for (int ligne = 1; ligne <= 3; ligne++)
{
    for (int col = 1; col <= 3; col++)
    {
        Console.Write($"{ligne * col,4}");
    }
    Console.WriteLine();
}
//    1   2   3
//    2   4   6
//    3   6   9

// Sortir de deux boucles : drapeau ou méthode dédiée
bool trouve = false;
for (int i = 0; i < 10 && !trouve; i++)
    for (int j = 0; j < 10; j++)
        if (grille[i, j] == cible) { trouve = true; break; }
  • break ne sort que de la boucle la plus interne.
  • continue évite un if englobant tout le corps : le code reste plat.
  • Pour quitter plusieurs niveaux : un drapeau booléen dans la condition, ou extraire la recherche dans une méthode et return (module 4).
  • Boucles imbriquées : complexité en n × m. Acceptable sur de petites données, à surveiller au-delà.
  • Dans un switch placé dans une boucle, break sort du switch, pas de la boucle.

Module 4 — Anatomie d'une méthode

Méthodes
// modificateurs  type-retour  Nom(paramètres)
static int Additionner(int a, int b)
{
    return a + b;
}

// Sans valeur de retour : void

{
    Console.WriteLine($"[INFO] {message}");
}

// Appel

Afficher("Démarrage");

{
    if (b == 0) return double.NaN;
    return a / b;
}

// Avec top-level statements, les méthodes se déclarent
// après le code principal, dans le même fichier.
  • Une méthode nomme un bloc de code réutilisable. Verbe à l'infinitif en PascalCase : CalculerTotal, EstValide.
  • Signature = nom + types des paramètres. Le type de retour n'en fait pas partie.
  • return termine la méthode et fournit la valeur. Une méthode non-void doit retourner sur tous les chemins.
  • Les gardes (early return) en début de méthode évitent l'imbrication.
  • static : la méthode appartient au type, pas à un objet (module 5). Obligatoire pour les méthodes déclarées à côté des top-level statements.
  • Règle de taille : une méthode fait une chose, tient sur un écran.

Module 4 — Passage de paramètres : valeur, ref, out, in, params

Modes de passage
// Par valeur (défaut) : copie, l'original n'est pas modifié
static void Incrementer(int n) { n++; }
int x = 5; Incrementer(x); // x vaut toujours 5

// ref : la méthode travaille sur la variable d'origine
static void IncrementerRef(ref int n) { n++; }
IncrementerRef(ref x);     // x vaut 6

// out : la méthode DOIT affecter le paramètre (sortie)
static bool Diviser(int a, int b, out int quotient)
{
    if (b == 0) { quotient = 0; return false; }
    quotient = a / b;
    return true;
}
if (Diviser(10, 3, out int q)) Console.WriteLine(q); // 3

// in : lecture seule, évite la copie des gros structs
static double Norme(in Vecteur v) => Math.Sqrt(v.X * v.X + v.Y * v.Y);

// params : nombre variable d'arguments
static int Somme(params int[] valeurs)
{
    int total = 0;
    foreach (int v in valeurs) total += v;
    return total;
}
Somme();  Somme(1);  Somme(1, 2, 3, 4);
  • Par défaut, un type valeur est copié : la méthode ne peut pas modifier l'original.
  • Un type référence est aussi passé par valeur… mais la valeur est l'adresse : la méthode peut modifier le contenu de l'objet (pas remplacer l'objet).
  • ref : rare en pratique, utile pour échanger deux variables ou optimiser.
  • out : le pattern TryXxx — un bool de succès + le résultat en sortie.
  • params : doit être le dernier paramètre. Depuis C# 13, accepte aussi params List<T> ou params ReadOnlySpan<T>.

Module 4 — Paramètres optionnels, nommés, surcharge

Souplesse d'appel
// Optionnels : valeur par défaut, doivent être en dernier
static void Saluer(string nom, string civilite = "M.", bool crier = false)
{
    string msg = $"Bonjour {civilite} {nom}";
    Console.WriteLine(crier ? msg.ToUpper() : msg);
}
Saluer("Dupont");                       // Bonjour M. Dupont
Saluer("Martin", "Mme");                // Bonjour Mme Martin
Saluer("Martin", crier: true);          // argument nommé, saute civilite
Saluer(civilite: "Dr", nom: "Leroy");   // ordre libre avec noms

// Surcharge : même nom, paramètres différents
static double Aire(double rayon) => Math.PI * rayon * rayon;
static double Aire(double largeur, double hauteur) => largeur * hauteur;
static double Aire(double a, double b, double c)  // triangle (Héron)
{
    double s = (a + b + c) / 2;
    return Math.Sqrt(s * (s - a) * (s - b) * (s - c));
}

Aire(2);        // disque
Aire(3, 4);     // rectangle
Aire(3, 4, 5);  // triangle
  • Les paramètres optionnels évitent de multiplier les surcharges pour des cas simples.
  • Les arguments nommés rendent l'appel lisible quand une méthode a plusieurs booléens : Exporter(fichier, inclureEntetes: true).
  • La surcharge = plusieurs méthodes du même nom distinguées par le nombre ou le type des paramètres. Le compilateur choisit la meilleure correspondance.
  • Une surcharge ne peut pas différer seulement par le type de retour.
  • Éviter les surcharges ambiguës (int/long/double) : appels difficiles à prédire.

Module 4 — Expression-bodied, fonctions locales, récursivité

Formes avancées
// Expression-bodied : méthode d'une seule expression
static bool EstPair(int n) => n % 2 == 0;
static string Nom(string p, string n) => $"{p} {n}";

// Fonction locale : visible uniquement dans la méthode hôte
static int SommeCarres(int[] valeurs)
{
    int total = 0;
    foreach (var v in valeurs) total += Carre(v);
    return total;

    static int Carre(int x) => x * x;   // fonction locale
}

// Récursivité : une méthode qui s'appelle elle-même
static long Factorielle(int n)
{
    if (n <= 1) return 1;                // cas de base
    return n * Factorielle(n - 1);       // cas récursif
}
Factorielle(5); // 120

// Parcours récursif d'une arborescence
static void Lister(string dossier, int niveau = 0)
{
    Console.WriteLine(new string(' ', niveau * 2) + Path.GetFileName(dossier));
    foreach (var sous in Directory.GetDirectories(dossier))
        Lister(sous, niveau + 1);
}
  • => (expression-bodied) : remplace { return …; } pour les méthodes d'une ligne. Ne pas confondre avec les lambdas (module 10).
  • Fonction locale : découper une méthode sans polluer la classe. static devant garantit qu'elle ne capture aucune variable externe.
  • Récursivité : toujours un cas de base qui arrête l'appel. Sinon StackOverflowException (non rattrapable).
  • Cas d'usage naturels : arborescences (fichiers, menus, JSON), algorithmes « diviser pour régner ».
  • Une boucle est souvent plus simple et plus rapide qu'une récursion : réserver la récursion aux structures récursives.

public class Stock
{
    private readonly Dictionary<string, int> _quantites = new();

    // Invariant : une quantité n'est jamais négative
    public void Retirer(string ref_, int qte)
    {
        if (qte <= 0)
            throw new ArgumentOutOfRangeException(nameof(qte));

        int actuelle = _quantites.GetValueOrDefault(ref_);
        if (actuelle < qte)
            throw new InvalidOperationException(
                $"Stock insuffisant pour {ref_} : {actuelle} < {qte}");

        _quantites[ref_] = actuelle - qte;
    }

    public int Quantite(string ref_) => _quantites.GetValueOrDefault(ref_);

    // readonly : la référence ne peut plus changer après le constructeur
    // (le contenu du dictionnaire, lui, reste modifiable)
}

Hiérarchie Document
// Classe de base (parent)
public class Document
{
    public string Titre { get; }
    public int Annee { get; }

    public Document(string titre, int annee)
    {
        Titre = titre;
        Annee = annee;
    }

}

// Classe dérivée (enfant) : hérite de tout ce qui n'est pas private
public class Livre : Document
{
    public string Isbn { get; }

    // base(…) appelle le constructeur du parent
    public Livre(string titre, int annee, string isbn)
        : base(titre, annee)

        Isbn = isbn;
    }
}

public class Revue : Document
{

        : base(titre, annee) => Numero = numero;

Document d = l;                    // un Livre EST un Document

  • Relation « est un » : un livre est un document. Si la phrase est fausse, ne pas hériter (préférer la composition « a un »).
  • Le constructeur de l'enfant doit appeler celui du parent avec : base(…) (sinon C# appelle base() sans argument, qui doit exister).
  • Une classe n'hérite que d'une seule classe (héritage simple). Les interfaces (module 7) lèvent cette limite.
  • Toute classe hérite implicitement de object.
  • protected : le compromis pour les membres réservés aux enfants.

Module 6 — virtual, override, sealed

Redéfinition
public class Document
{
    public string Titre { get; }
    public Document(string titre) => Titre = titre;

    // virtual : l'enfant PEUT redéfinir
    public virtual decimal FraisRetard(int jours) => jours * 0.10m;

    public virtual string Decrire() => $"Document : {Titre}";
}

public class Livre : Document
{
    public Livre(string titre) : base(titre) { }

    // override : redéfinition
    public override decimal FraisRetard(int jours) => jours * 0.25m;

    // Réutiliser la version parente
    public override string Decrire() => $"Livre — {base.Decrire()}";
}

public class LivreRare : Livre
{
    public LivreRare(string titre) : base(titre) { }

    // sealed : plus personne ne pourra redéfinir en dessous
    public sealed override decimal FraisRetard(int jours) => jours * 2m;
}

// Polymorphisme : la méthode appelée dépend du type RÉEL
Document[] docs = { new Document("Note"), new Livre("Clean Code"), new LivreRare("Manuscrit") };
foreach (var d in docs)
    Console.WriteLine($"{d.Titre} : {d.FraisRetard(10)} €");
// Note : 1,00 €   Clean Code : 2,50 €   Manuscrit : 20,00 €
  • virtual sur le parent + override sur l'enfant = polymorphisme : le bon comportement est choisi à l'exécution selon le type concret.
  • Sans virtual, une méthode ne peut pas être redéfinie (le compilateur refuse override).
  • base.Methode() : appeler la version du parent depuis la redéfinition (enrichir plutôt que remplacer).
  • sealed override : verrouille la chaîne. sealed class : interdit tout héritage de la classe.
  • new (masquage) existe aussi mais casse le polymorphisme : à éviter.

Module 6 — Classes abstraites

Forme.cs
// abstract : incomplète, ne peut pas être instanciée
public abstract class Forme
{
    public string Nom { get; }
    protected Forme(string nom) => Nom = nom;

    // Méthode abstraite : pas de corps, l'enfant DOIT l'implémenter
    public abstract double Aire();

    // Méthode concrète : partagée, s'appuie sur l'abstraite
    public string Decrire() => $"{Nom} : aire = {Aire():F2}";
}

public class Cercle : Forme
{
    public double Rayon { get; }
    public Cercle(double rayon) : base("Cercle") => Rayon = rayon;
    public override double Aire() => Math.PI * Rayon * Rayon;
}

public class Rectangle : Forme
{
    public double L { get; }
    public double H { get; }
    public Rectangle(double l, double h) : base("Rectangle") { L = l; H = h; }
    public override double Aire() => L * H;
}

// var f = new Forme("?");  // erreur : classe abstraite
Forme[] formes = { new Cercle(1), new Rectangle(2, 3) };
foreach (var f in formes) Console.WriteLine(f.Decrire());
  • Une classe abstract définit un contrat partiel : du code commun + des trous (abstract) que chaque enfant remplit.
  • Une méthode abstraite est implicitement virtual et se redéfinit avec override.
  • Un enfant qui n'implémente pas toutes les méthodes abstraites doit lui-même être abstract.
  • Pattern Template Method : la méthode concrète Decrire() orchestre, l'abstraite Aire() varie.
  • Abstraite vs interface (module 7) : la classe abstraite fournit de l'implémentation et un constructeur ; l'interface ne définit que la forme.

Module 6 — ToString, Equals, GetHashCode

Membres hérités d'object
public class Livre
{

    public string Titre { get; }
    public Livre(string isbn, string titre) { Isbn = isbn; Titre = titre; }

Module 7 — Interfaces : définir un contrat

IEmpruntable.cs
// Une interface décrit CE QUE fait un type, pas COMMENT
public interface IEmpruntable
{
    bool Disponible { get; }
    int DureeMaxJours { get; }
    void Emprunter(Membre membre);
    void Rendre();
}

public class Livre : IEmpruntable
{
    public bool Disponible { get; private set; } = true;
    public int DureeMaxJours => 21;

    public void Emprunter(Membre membre)
    {
        if (!Disponible) throw new InvalidOperationException("Déjà emprunté");
        Disponible = false;
    }

    public void Rendre() => Disponible = true;
}

public class Dvd : IEmpruntable
{
    public bool Disponible { get; private set; } = true;
    public int DureeMaxJours => 7;
    public void Emprunter(Membre membre) => Disponible = false;
    public void Rendre() => Disponible = true;
}

// Le code client ne dépend que de l'interface
static void Preter(IEmpruntable item, Membre m)
{
    item.Emprunter(m);
    Console.WriteLine($"À rendre sous {item.DureeMaxJours} jours");
}
  • Une interface liste des membres (méthodes, propriétés, événements) sans implémentation. Préfixe I par convention.
  • Une classe qui « implémente » l'interface s'engage à fournir tous ses membres, en public.
  • Une classe peut implémenter plusieurs interfaces (contrairement à l'héritage simple).
  • Le code client (Preter) accepte n'importe quel IEmpruntable, présent ou futur : c'est le découplage.
  • Une interface n'a ni constructeur ni champ. Depuis C# 8, elle peut avoir des implémentations par défaut, mais c'est rare.

object[] items = { new Livre("978-1", "Clean Code"), new Dvd("Matrix"), "chaîne", 42 };

        Livre l                        => $"Livre : {l.Titre}",
        Dvd d                          => $"DVD : {d.Titre}",

        int n when n > 0               => $"Entier positif : {n}",
        null                           => "null",
        _                              => $"Inconnu : {item.GetType().Name}"
    };
    Console.WriteLine(description);
}

    public IReadOnlyList<Livre> Livres => _livres;

Module 10 — Delegates : Func, Action, Predicate

Delegates
// Un delegate est un type qui référence une méthode
// Func<entrées…, sortie>   Action<entrées…> (void)   Predicate<T> (→ bool)

Func<int, int, int> additionner = Additionner;
Func<int, int, int> multiplier = (a, b) => a * b;
Action<string> afficher = msg => Console.WriteLine($"> {msg}");
Predicate<int> estPair = n => n % 2 == 0;

additionner(2, 3);       // 5
multiplier(2, 3);        // 6
afficher("Bonjour");
estPair(4);              // true

static int Additionner(int a, int b) => a + b;

// Passer un comportement en paramètre
static List<T> Filtrer<T>(IEnumerable<T> source, Func<T, bool> critere)
{
    var resultat = new List<T>();
    foreach (var item in source)
        if (critere(item)) resultat.Add(item);
    return resultat;
}

var pairs = Filtrer(new[] { 1, 2, 3, 4 }, n => n % 2 == 0);        // [2, 4]
var longs = Filtrer(livres, l => l.Titre.Length > 10);

// Stocker des actions à exécuter plus tard
var commandes = new Dictionary<string, Action>
{
    ["1"] = () => biblio.ListerLivres(),
    ["2"] = () => Console.WriteLine("Ajout…"),
    ["q"] = () => Environment.Exit(0)
};
commandes.GetValueOrDefault(choix, () => Console.WriteLine("?"))();
  • Un delegate permet de traiter une méthode comme une valeur : la stocker, la passer, la renvoyer.
  • Func<…, TResult> : le dernier type est le retour. Action<…> : pas de retour. Predicate<T> ≡ Func<T, bool>.
  • C'est le mécanisme derrière LINQ : Where(l => …) reçoit un Func<Livre, bool>.
  • Le menu par dictionnaire d'Action remplace un long switch et s'étend sans modifier la boucle.
  • Les event (hors périmètre) sont des delegates multi-abonnés.

Lambdas
// Syntaxe : (paramètres) => expression   ou   (paramètres) => { bloc }
Func<int, int> carre = x => x * x;              // 1 paramètre : parenthèses optionnelles
Func<int, int, int> add = (a, b) => a + b;      // 2 paramètres

Func<double, double> demi = (double x) => x / 2;

// Capture de variables (closure) : la lambda "voit" son contexte
int seuil = 10;
Func<int, bool> depasse = n => n > seuil;

depasse(50);                 // false

livres.Where(EstDisponible);

// Lambda statique : interdit toute capture (performance, clarté)
Func<int, int> doubler = static x => x * 2;

  • => se lit « va vers » : x va vers x au carré.
  • Closure : la lambda capture les variables de son entourage par référence. Utile (compteurs, configuration), mais surprenant si la variable change ensuite.
  • Une lambda longue (> 3 lignes) mérite de devenir une méthode nommée : plus lisible, testable, réutilisable.
  • Ne pas confondre : => d'une méthode expression-bodied (module 4) et => d'une lambda — même symbole, contextes différents.

Les trois fondamentaux

  • L'ordre du pipeline a un impact : Where tôt, Select tard, OrderBy sur le plus petit ensemble possible.

// Certains objets tiennent des ressources non gérées par le GC :
// fichiers, connexions réseau/BD, sockets… Ils implémentent IDisposable.

// Forme classique : Dispose() garanti à la fin du bloc
using (var lecteur = new StreamReader("livres.csv"))
{
    string? ligne;
    while ((ligne = lecteur.ReadLine()) != null)
        Console.WriteLine(ligne);
}   // ← lecteur.Dispose() appelé ici, même en cas d'exception

// Forme déclaration (C# 8+) : Dispose() à la fin de la portée
using var writer = new StreamWriter("journal.log", append: true);
writer.WriteLine($"{DateTime.Now:O} démarrage");
// … Dispose() à la fin de la méthode / du bloc englobant

// Équivalent sans using (à ne pas écrire à la main)
var w = new StreamWriter("x.txt");
try { w.WriteLine("…"); }
finally { w.Dispose(); }

// Implémenter IDisposable dans sa propre classe
public class Session : IDisposable
{
    private readonly StreamWriter _log = new("session.log");
    public void Ecrire(string m) => _log.WriteLine(m);

    public void Dispose()
    {
        _log.Dispose();
        GC.SuppressFinalize(this);
    }
}

using var s = new Session();

  • Règle : dès qu'un type expose Dispose(), l'utiliser avec using. StreamReader, StreamWriter, FileStream, HttpClient, SqlConnection…
  • using var : plus court, se termine à la fin du bloc englobant. Attention à ne pas garder la ressource ouverte trop longtemps.
  • Si votre classe possède un IDisposable, elle doit elle-même être IDisposable.

  • Avec Nullable activé, string signifie « jamais null » et string? « peut être null ». Le compilateur avertit quand on ignore cette distinction.
  • Ce sont des avertissements, pas des erreurs : le programme compile, mais chaque warning est un NullReferenceException potentiel.
  • Objectif : zéro warning (critère de la grille d'évaluation). Traiter la nullabilité aux frontières (saisie, fichier, recherche) et propager des types non nullables ensuite.
  • ! désactive l'analyse pour une expression : réservé aux cas où l'on a une preuve que le compilateur ne voit pas.
  • Types valeur : int? reste un vrai Nullable<int> (module 3).
